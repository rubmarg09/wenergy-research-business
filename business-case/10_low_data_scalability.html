Chapter 10 / 12

Less data should mean less certainty — not zero product.

Wenergy's long-term scalability depends on functioning beyond territories with rich French open-data infrastructure. The product therefore needs an evidence-adaptive operating model that remains useful when data are partial, inconsistent or sparse.

Evidence Adaptive Low Data Low Compute Internationalisable
Three Evidence Environments

The same product logic — different confidence.

HIGH-DATA

Rich territorial evidence

Strong public datasets, building information, actor context, energy evidence and planning layers.

  • more observed inputs;
  • higher screening confidence;
  • richer automation;
  • fewer initial data gaps.
H
PARTIAL-DATA

Mixed observed and estimated evidence

Some authoritative datasets exist, but key facilities, actors or resource characteristics require estimation or local confirmation.

  • observed + estimated mix;
  • explicit uncertainty;
  • targeted data collection;
  • selective manual inputs.
P
LOW-DATA

Sparse but not unusable

Minimal reliable information is combined with transparent proxies, broad ranges, local evidence collection and professional validation.

  • coarser project screening;
  • larger uncertainty bands;
  • Data-Gap Lenses;
  • progressive evidence building.
L
SAME PRODUCT OBJECTS — DIFFERENT EVIDENCE DENSITY — DIFFERENT CONFIDENCE.
Confidence Architecture

Confidence should degrade transparently.

HIGH Strong observed evidence.
MEDIUM-HIGH Mostly observed with limited assumptions.
MEDIUM Mixed observed and estimated evidence.
LOW-MEDIUM Significant uncertainty or data gaps.
LOW Early screening / proxy-led candidate.
MISSING DATA MUST LOWER CONFIDENCE — NOT BE SILENTLY REPLACED BY INVENTED PRECISION.

Low-data deployment should improve itself over time.

Product Principle

Data gaps are not product failures.

When Wenergy cannot support a high-confidence conclusion, the system should explain:

  • what is missing;
  • why it matters;
  • who might provide it;
  • what evidence class it would become;
  • how the Lens should change afterward.
Minimum Viable Evidence

Start with what can be trusted.

Global / Open Data OpenStreetMap, global climate/resource layers and other broadly available sources.
Manual Facilities Local teams can identify important buildings, sites and infrastructure directly.
Published Factors Use documented conversion factors or ranges rather than unsupported guesses.
Actor Confirmation Upgrade uncertain evidence through structured local contribution.
Territory Adapter Architecture

Scale the framework — adapt the inputs.

Administrative Adapter Local geography, boundaries and government structure.
Energy Data Adapter Available local generation, consumption and resource sources.
Constraint Adapter Planning, environmental and land-use context.
Actor Adapter Local public, commercial, agricultural and professional entities.
Building Adapter Available footprints, addresses and facility information.
Policy Adapter Local programmes, incentives and governance.
Language Adapter Translation and terminology.
Evidence Adapter Map local data quality to the common evidence taxonomy.
STANDARDISE THE PROJECT MODEL — LOCALISE THE EVIDENCE CONNECTIONS.
Low-Compute Design

Scalability should not require expensive infrastructure everywhere.

No GPU Requirement Basic Wenergy screening should run without specialist hardware.
Deterministic Core High-volume numerical logic stays outside large language models.
Cache Stable Outputs Reuse expensive calculations when source evidence has not changed.
Selective AI Use LLMs only where language extraction or explanation adds value.
Low-Bandwidth Access

A useful territorial platform should not require perfect connectivity.

Lightweight Pages Keep community-facing interfaces efficient.
Progressive Loading Load deeper geospatial information only when required.
Cached Project Lenses Allow important project information to remain accessible.
Exportable Evidence Support printable or shareable project summaries.

Internationalisation

The universal problem is fragmentation. The local implementation is evidence-specific.

Language Translate interfaces and explanations.
Units Adapt technical and financial units.
Governance Map local institutional roles.
Data Swap national data connectors.
Professional Standards Adapt project handoff requirements.
INTERNATIONAL SCALABILITY ≠ ONE UNIVERSAL DATA PIPELINE.
AI in Low-Data Environments

Language models can help structure uncertainty — not erase it.

Appropriate Uses

Assist the evidence workflow

Extract structured fields from documents.
Categorise local evidence.
Translate stakeholder information.
Explain Project Lenses.
Suggest validation questions.
Not Acceptable

Do not manufacture facts

Invent unavailable consumption data.
Fabricate actor willingness.
Turn uncertain estimates into observed facts.
Override deterministic evidence without review.
Hide missing source provenance.
LLM OUTPUT ≠ OBSERVED FACT
Scalability KPIs

Scale should be measured in reuse and evidence quality — not territory count alone.

≥70% Workflow reuse on second territory.
↓ Onboarding hours per new territory.
↑ Share of reusable connectors / adapters.
≥90% Evidence provenance target for priority outputs.
↓ Compute cost per Project Lens.
↑ Actor-confirmed evidence rate.
↑ Cross-territory pathway reuse.
0 Invented evidence tolerated.
Expansion Gates

Wenergy should earn the right to scale.

Gate 1 — Foix Value Does a real territory find the prioritisation useful?
Gate 2 — Foix Payment Is there evidence of willingness to pay?
Gate 3 — Second Territory Can the workflow be reused without rebuilding the product?
Gate 4 — Recurring Use Does value persist after the first scan?
DO NOT INTERNATIONALISE A WORKFLOW THAT HAS NOT YET PROVEN REPEATABLE LOCALLY.
LOW-DATA MODE IS NOT A LOWER-QUALITY VERSION OF WENERGY. It is a different evidence state: more explicit uncertainty, more local contribution, wider ranges, more data gaps and stronger validation gates — while preserving the same core Project Lens and decision workflow.
